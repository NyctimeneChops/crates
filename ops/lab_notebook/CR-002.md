## F5. The crawler design existed in no versioned file

The full design (category-scoped ranking, presence-gated base with bounded
bonuses, binary section coverage with equal-duration bins as fallback, per-session
scores capped at 1 then summed, backup folders as a distinct retained class, Drum
Rack chain resolution via receive note ranges, the six-step categorisation
cascade, the five-table Parquet schema, the sensitivity sweep) appeared only in a
session handoff document. Verified absent from all six planning documents by
searching for Parquet, `chain_id`, `occurrences`, cascade, sensitivity, section
coverage, `category_overrides`, Drum Rack, and Backup.

Designed in conversation after 2026-07-21 and never written back. Now written into
`technical-architecture.md` as **§3.6, an amendment** rather than a rewrite,
marked as later and winning where it disagrees with §§3.1 to 3.5.

Two supersessions are explicit. **"Survived to end of session" is dropped from
v1** because it is not observable from a single saved `.als`; a saved set is the
end state, so everything visible survived by definition. And **audible or timeline
extent is rejected as a base signal** because it measures sustain and density,
which track instrument role rather than commitment, with systematic bias: pads
score high for doing nothing, a defining one-shot scores low.

Two items preserved verbatim because they are the parser's actual difficulty:
**Drum Rack chain resolution is the parser's main job for the flagship output, not
a refinement.** And **backup folders are retained and indexed as a distinct class,
not excluded**, because they are a free automatic revision history.

## F6. `inventory.py` had five bugs, not two

Two were known. Three were found on 2026-07-25.

1. `FACTORY_HINTS` contained `r"\packs\\"`, a raw string whose two trailing
   backslashes could never match a real path.
2. `os.walk(..., onerror=lambda e: None)` swallowed permission errors, so an
   unknown number of directories were skipped without record. **This directly
   corrupts N**, the one number the script exists to produce.
3. **Successful reads were counted as failures.** An uncompressed `.als` returned
   `header_status = "not_gzip"` even on success, and `summarize()` counted
   anything other than `"ok"` as a header read problem. An uncompressed set is
   legal, not an error.
4. The docstring claimed the script "reads only the gzip header region." It also
   content-hashes every byte of every file found, including all backups. On a deep
   revision history that dominates runtime and was invisible before launch.
5. **A single loose `.als` anywhere counted as a project.** `classify()` returned
   `primary` when `len(siblings_als) <= 3`, and the list included the file itself,
   so one stray set in a downloads folder inflated N.

All five fixed. Design changes made while fixing them:

- A `classify_reason` column records which rule fired for every file, and the
  summary reports strong classifications (real project folders) separately from
  **weak** ones (the loose-file heuristic), with an explicit warning when the weak
  share is material. N is now auditable instead of taken on faith.
- Unreadable directories are counted and the first ten are printed, with N
  labelled a **lower bound** whenever any exist.
- `was_gzip` became its own column so "uncompressed but fine" stops reading as a
  failure.
- `--no-hash` added, since hashing is only needed for duplicate detection.
- The per-file parent-directory glob is cached per directory. It previously ran
  once per file, so cost scaled as files times directory size.

## What I learned

**Documentation drifts fastest in the week it is written.** Every one of the
twelve disagreements was introduced between 2026-07-21 and 2026-07-25, in a
document set produced on a single day by someone paying close attention. The
lesson is not to write more carefully. It is that a document set with no
precedence rule will disagree with itself, and the disagreements will not be
visible from inside any single document.

**Unversioned work is the recurring failure, not a one-off.** `inventory.py` and,
in a separate project on the same day, four theory documents. Both times the
artifact was the most concentrated thinking available and both times it sat
outside the version control built to protect it. Neither was withheld
deliberately, which is exactly why a rule is needed rather than more care.

**A summary that loses a design is worse than no summary.** The handoff was
accurate about everything it covered and silently dropped the entire settled
crawler specification. Anyone working from it alone would have rebuilt that design
from scratch or, worse, built something different.

## Precedence rule adopted

Twelve disagreements in one document set is a sign that no rule existed for
resolving them. One now does:

1. **On what exists, the repository wins.** Documents describe intent; the tree is
   fact.
2. **On disputed fact, `CR-` notebook entries win**, being append-only and dated.
3. **Then `synthesis.md`**, which already declares itself the parent.
4. **Then the remaining documents.**
5. **Session handoff documents lose to all of the above.** They are lossy
   summaries by design and they are not versioned.
